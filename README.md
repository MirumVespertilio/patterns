## Описание

Программа реализует систему управления заказами для кофейни с командно-текстовым интерфейсом. Пользователь может создавать заказы, добавлять напитки с различными добавками, сохранять и загружать заказы из файла.

### Основные возможности:

- 📝 Создание заказов с несколькими напитками
- 🎨 Добавление добавок к напиткам (молоко, сироп, сливки)
- 📋 Просмотр всех заказов
- 🗑️ Удаление заказов
- 💾 Сохранение и загрузка заказов из JSON-файла
- 🔬 Демонстрация работы паттерна Singleton

## Паттерны проектирования

### 🔒 Singleton (Одиночка)

**Назначение:** Гарантирует, что у класса есть только один экземпляр, и предоставляет глобальную точку доступа к нему.

**Применение:** Класс `OrderManager` реализован как Singleton. Это обеспечивает:
- Единое хранилище всех заказов
- Единую нумерацию заказов
- Отсутствие конфликтов при работе с данными

```python
# Получение единственного экземпляра
manager = OrderManager.get_instance()

# Любой способ создания возвращает тот же объект
manager2 = OrderManager()
manager3 = OrderManager.get_instance()

print(manager is manager2)  # True
print(manager is manager3)  # True
```

### 🎨 Decorator (Декоратор)

**Назначение:** Позволяет динамически добавлять объектам новую функциональность, оборачивая их в полезные "обёртки".

**Применение:** Добавки к напиткам реализованы как декораторы:
- `MilkDecorator` — добавляет молоко (+30₽)
- `SyrupDecorator` — добавляет сироп (+40₽)
- `CreamDecorator` — добавляет взбитые сливки (+50₽)

```python
# Создаём базовый напиток
coffee = Coffee()  # 150₽

# Добавляем молоко
coffee_with_milk = MilkDecorator(coffee)  # 180₽

# Добавляем сироп
coffee_full = SyrupDecorator(coffee_with_milk, "ванильный")  # 220₽

print(coffee_full.get_description())  # "Кофе, Молоко, Сироп ванильный"
print(coffee_full.get_cost())         # 220.0
```

## Архитектура

### Принципы SOLID

| Принцип | Применение |
|---------|------------|
| **S** — Single Responsibility | Каждый класс отвечает за одну задачу: `Beverage` — описание напитка, `Order` — хранение заказа, `OrderManager` — управление заказами |
| **O** — Open/Closed | Новые напитки и добавки добавляются без изменения существующего кода (новые классы-наследники) |
| **L** — Liskov Substitution | Любой декоратор можно использовать вместо `Beverage` |
| **I** — Interface Segregation | Минимальные абстрактные методы в базовых классах |
| **D** — Dependency Inversion | `OrderManager` работает с абстракцией `Order` |

## Тестирование

### Проверка Singleton

```python
from manager import OrderManager

# Сброс предыдущего состояния (для тестов)
OrderManager.reset_instance()

# Получаем экземпляры разными способами
m1 = OrderManager.get_instance()
m2 = OrderManager()
m3 = OrderManager.get_instance()

# Проверяем, что это один и тот же объект
assert m1 is m2, "Singleton не работает!"
assert m1 is m3, "Singleton не работает!"
assert id(m1) == id(m2) == id(m3), "Разные ID!"

print("✅ Singleton работает корректно")
```

### Проверка Decorator

```python
from models import Coffee, MilkDecorator, SyrupDecorator

# Базовый напиток
coffee = Coffee()
assert coffee.get_cost() == 150.0
assert coffee.get_description() == "Кофе"

# С молоком
coffee_milk = MilkDecorator(coffee)
assert coffee_milk.get_cost() == 180.0
assert "Молоко" in coffee_milk.get_description()

# С сиропом
coffee_full = SyrupDecorator(coffee_milk, "ванильный")
assert coffee_full.get_cost() == 220.0
assert "Сироп ванильный" in coffee_full.get_description()

print("✅ Decorator работает корректно")
```

### Проверка хранилища

```python
from manager import OrderManager
from storage import save_orders, load_orders

# Создаём заказ
manager = OrderManager.get_instance()
order = manager.create_order()
order.add_beverage(Coffee())

# Сохраняем
save_orders(manager.get_all_orders(), "test_orders.json")

# Загружаем
loaded = load_orders("test_orders.json")
assert len(loaded) == 1
assert loaded[0].order_id == 1

print("✅ Хранилище работает корректно")
```
